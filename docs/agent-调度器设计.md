# Agent 调度器设计

核心模式：**工具调用循环（ReAct loop）**——LLM 输出若含 tool_call，执行工具并把结果回传，LLM 继续生成，直到无调用为止。这是行业标准模式（OpenAI Function Calling / Vercel AI SDK multi-step 均为此模式）。

## 核心架构

```
用户消息
   ↓
①会话管理 ── 取历史消息、当前模型、成员身份
   ↓
②系统提示词构建 ── 人设 + 家庭信息 + 权限内工具清单 + 时间/农历
   ↓
③LLM 网关 ── 路由到选中模型（海外/国内/本地），SSE 流式
   ↓
④工具调用循环(ReAct) ── LLM 输出含 tool_call? ──是──> ⑤执行 ──> 结果回传 ──> 回到④
   ↓ 否
⑥流式回复 + 结果卡片(可撤销)
```

## 六个核心组件

### ① 会话管理

- 会话 = 会话ID + 成员ID + 当前模型 + 历史消息（user/assistant/tool_call/tool_result）
- 上下文窗口管理：超长历史自动截断或摘要，控 token 成本
- 会话按成员严格隔离

### ② 系统提示词构建器（差异化关键）

- 基础人设 + 家庭成员/角色信息 + **该用户权限内的工具清单** + 当前时间/农历
- 按角色切语气：老人简洁、小孩活泼
- **安全核心：只把有权限的工具注入提示词，从源头防越权**，不只靠执行时校验

### ③ LLM 网关（多供应商抽象）

- 统一 `Provider` 接口，适配 OpenAI/Anthropic/DeepSeek/智谱/Ollama
- 封装流式 + Function Calling，屏蔽供应商差异
- 会话内切模型：前端传 `modelId`，网关路由到对应供应商，工具集不变
- 凭证从加密存储读取，绝不落明文
- **用量统计埋点在这里**（token/成本），供系统管理模块统计

### ④ 工具调用循环（ReAct loop）

- 循环：LLM 输出 → 含 tool_call 就执行 → 结果回传 → LLM 继续 → 直到无调用
- **最大步数上限**（危险分级控制，见下）防死循环
- 每步状态实时推前端（"正在记账…"）

### ⑤ 工具执行器

- 执行前：**权限校验 + 参数校验（JSON Schema）**
- 执行：调业务模块 service
- 执行后：生成**结果卡片** + 写**审计日志**（涉钱/权限操作）+ 同步记录**撤销数据**

### ⑥ 结果卡片

- 结构化返回（工具名/参数/结果/可撤销标记），前端渲染成卡片 + 撤销按钮

## 工具注册表设计

| 字段               | 说明                             |
| ------------------ | -------------------------------- |
| name / description | 供 LLM 选择                      |
| inputSchema        | JSON Schema 参数定义             |
| handler            | 执行函数                         |
| undoHandler        | 撤销函数（写操作必填，查询留空） |
| risk_level         | 低/中/高 → 控循环上限与确认策略  |
| 所需权限           | 与权限矩阵联动，按用户过滤注入   |
| 所属模块           | 家务/财务/日程/购物/用餐/系统    |

**工具清单示例**（一期）：

- 财务：`record_expense`(金额/类别)、`query_budget`
- 家务：`assign_task`、`complete_task`、`list_my_tasks`
- 用餐：`report_meal`(是否在家吃)、`suggest_dinner`、`add_recipe_ingredients_to_list`
- 系统：`switch_model`、`list_models`

## 危险分级控制

每个工具声明 `risk_level`，调度器据此控制循环与确认：

| 等级                     | 示例工具                                   | 循环上限 | 执行前确认                         | 撤销           |
| ------------------------ | ------------------------------------------ | -------- | ---------------------------------- | -------------- |
| **低（查询类）**         | 查我的任务 / 查预算 / 推荐晚餐 / 列模型    | 15 步    | 否                                 | 不需要         |
| **中（创建/修改）**      | 派任务 / 打卡 / 报饭 / 加购物清单 / 切模型 | 8 步     | 否                                 | 可撤销         |
| **高（财务/删除/权限）** | 记账 / 改预算 / 删任务 / 改权限            | 3 步     | 可配置二次确认（对老人小孩建议开） | **必须可撤销** |

**双重控制**：循环既受全局上限（防死循环）约束，也受"累计风险"约束——一次对话中若已执行多个高风险工具，提前终止并提示"涉及金额操作较多，建议人工确认"。

## 撤销机制（V1 同步落地）

```
工具执行成功 → 同步写 undo_log（存逆向数据，如账单ID）→ 卡片带「撤销」按钮
   ↓ 用户点撤销
undo API → 按 tool 路由到 Undo() → 软删除/状态回滚 → 标记 undo_log 已用 → 记审计
```

- **工具接口**：写操作必须实现 `Undo()`，查询类不实现（编译期约束）
- **undo_log 表**：`id / user_id / tool_name / params / undo_data / expires_at / status`
- **有效期 24h**，超时自动失效（cron 清理）
- **撤销联动审计**：撤销本身也留痕，财务链路完整可查
- **级联回滚**：如"记账+自动归类"组合操作，撤销时一并回滚关联数据

## 数据流示例

> "今天买菜花了 120"

会话 → 提示词注入财务工具 → LLM → `tool_call(record_expense{amount:120, hint:"买菜"})` → 权限+参数校验 → 记账入库 + 同步写 undo_log + 审计 → 卡片「已记账 ¥120 · 食材」→ 结果回传 LLM → LLM 回复"已记上，食材类 120 元" → 前端显示卡片（可撤销）

## 关键设计决策

1. **权限双保险**：提示词层过滤（源头）+ 执行层校验（兜底）
2. **所有写操作可撤销**：工具实现 undo，卡片一键回滚
3. **流式可恢复**：会话状态持久化，SSE 断线重连能续上
4. **用量埋点在网关**：自动覆盖所有供应商调用
5. **模型切换不影响工具**：工具集与模型解耦，换模型只换路由

## Go 实现要点

- 接口定义：`Provider` 接口（统一流式+工具调用）、`Tool` 接口（含可选 `Undo()`）
- `go-openai` 处理 OpenAI 兼容供应商；Anthropic/Ollama 单独适配
- 并发：goroutine 处理流式，channel 传递 SSE 事件
- 工具注册：启动时注册到全局 registry，支持 Feature Flag 灰度
