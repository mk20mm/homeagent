## 0. 结论摘要

五个判断，构成全文骨架：

| #      | 判断                                                                                                                                                                                                                                    | 依据    |
| ------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------- |
| **E1** | 家庭事务的真正痛点不是"记录"，而是**"收口"和"盯"**。家庭是 3–8 人的**弱协作组织**——没有流程、没有 KPI，全靠默契和吼。产品的对手不是某个 App，是**负责收口的那个人脑子里的清单**（通常是做饭/管账的那位）。                              | §1      |
| **E2** | 四模块（家务/用餐/账单/日程）覆盖的是**"每天都发生的事"**，是家庭事务的**高频层**。还有三层完全在视野外：**供给层**（东西从哪来：采购与囤货）、**记忆层**（过去与未来的凭证：档案与纪念日）、**健康层**（最被忽视、信任门槛最高）。     | §2 / §3 |
| **E3** | **采购与囤货是唯一值得进 V1 的第五模块**——它是"跑腿"主脉最硬的落点，且与账单/用餐/日程三模块天然联动（记账→归类、菜谱→缺食材、周末采购提醒）。其余两个（家庭档案、健康关怀）**信任建立前不应碰**，留 V2/V3。                            | §4      |
| **E4** | AI 的不可替代性不在"理解"，而在**主动盯 + 跨模块编排 + 学习惯**。这三件事当前实现度分别为 0 / 0 / 部分（分类记忆未做）。**没有主动服务底座（C4/C5），上面所有模块都只是"又一个要打开的 App"**——这再次印证 C4/C5 前移到阶段 A 的正确性。 | §5      |
| **E5** | 边界必须守住：**不做社交、不做电商代购、不做金融、不做位置共享**。这四件事每一件都会把产品从"家事中枢"拽成另一个东西。新增模块的筛选线只有一条：**它是否替"收口者"省了一次脑子**。                                                      | §6      |

**一句话收口**：这个产品的终局不是"功能更多"，而是**"家人想起它的次数变少"**——因为它已经替你想完了。

## 1. 家庭事务的本质：一个弱协作组织的运营学

### 1.1 家庭与公司的区别（决定了产品形态）

| 维度     | 公司                | 家庭                           | 对产品的含义                                         |
| -------- | ------------------- | ------------------------------ | ---------------------------------------------------- |
| 协作模式 | 流程 + KPI + 工具链 | 默契 + 吼 + 群聊               | 不能照搬项目管理工具（子任务/甘特图/审批流都太重）   |
| 责任划分 | 岗位职责            | 谁顺手谁做 / 谁被念叨谁做      | **责任划分本身需要被产品显式化**（谁的名下、轮到谁） |
| 信息流   | 会议 + 文档 + 邮件  | 群聊碎片 + 人脑记忆            | 单一事实源的价值在此，而非"多一个录入入口"           |
| 成员构成 | 同质化的成年人      | 跨代际：老人怕点错、小孩需受限 | 输入必须分层（一句话 / 一键 / 大按钮），权限必须内置 |
| 目标     | 产出与效率          | **运转平稳 + 谁都别太累**      | 成功指标不是"记了多少笔"，而是"收口者省了多少脑子"   |

### 1.2 "收口者"画像（产品的真实主用户）

每个家都有一个人在承担**收口**的角色：记得谁还没报饭、账单快到期了、纸巾快没了、老人该体检了、孩子的疫苗时间。这个人**不是"记账人"**——记账只是他收口的六七件事之一。

**推论**：产品如果只做记账，只省了收口者 1/7 的脑子；产品如果把"记得"和"盯着"系统化，**才真正兑现了"动嘴，系统跑腿"的理念**。这也是为什么四模块之外的事必须被看见——**它们本来就是收口者清单上的东西**。

### 1.3 家庭事务的四个特征（模块筛选的判据）

| 特征           | 说明                                       | 判据（模块必须至少命中一条）                       |
| -------------- | ------------------------------------------ | -------------------------------------------------- |
| **重复性**     | 每天每周每月都在发生（报饭/打卡/缴费）     | 重复性 → 主动提醒 + 缺口 有用武之地                |
| **责任可划分** | 有明确的"该谁做"或"轮到谁"                 | 责任 → 派单 + 轮值 + 公平感视图 有用武之地         |
| **共享记忆**   | 一家人需要同一份"过去"（账单/档案/纪念日） | 共享 → 单一事实源 + 可追溯 有用武之地              |
| **外部依赖**   | 事情最终要在外面办完（缴费/采购/就诊）     | 外部 → 清单/提醒/凭证 有用武之地（但**不做代办**） |

## 3. 四模块之外的增量模块盘点

| 模块                | 家庭痛点（收口者视角）             | 重复性 | 责任可划分 | 共享记忆 | 外部依赖 | 判定                         |
| ------------------- | ---------------------------------- | ------ | ---------- | -------- | -------- | ---------------------------- |
| **★采购与囤货**     | 纸/米/洗护永远用完才发现           | 高     | 有（谁买） | 部分     | **强**   | **V1**                       |
| **★家庭档案**       | 保单在哪、保修期过了没、病历找不着 | 低     | 弱         | **强**   | 中       | V2                           |
| **★用药与健康关怀** | 老人该吃药了、体检/疫苗时间到了    | **高** | 有（谁管） | 强       | 强       | V2/V3                        |
| ★家庭投票/决策      | 周末去哪、大件买不买               | 低     | 无（平等） | 强       | 无       | V3                           |
| ★学校/物业通知      | 群里通知被淹没                     | 中     | 无         | 强       | 强       | V3（导入不做代办）           |
| ★家政/维修对接      | 找人难、约时间难                   | 低     | 有         | 弱       | **强**   | V3（只做信息聚合，不做交易） |

**筛选线（唯一判据）**：**它是否替收口者省了一次脑子？** 采购与囤货每天/每周都在发生且痛点最硬（"又用完了"）；档案与健康是"焦虑驱动"——低频但**出事时极其重要**，适合在信任建立后承接；投票与外部通知是"锦上添花"，且容易把产品带向社交与信息流，留 V3。

## 4. 三个增量模块的深论证

### 4.1 采购与囤货 · 建议进 V1（第五模块）

**用户问题**：卫生纸、米面、洗护用品、滤芯——永远是**用完的那一刻**才发现，而且总是最不方便的时候（晚上/下雨/来客人）。当前解法是"想起来才买"和"群里喊一声"。

**为什么线上化**：耗材的余量是**可以被记录和预测的**（每次用完记一次 → 系统知道大概周期）。这是"跑腿"主脉最硬的落点：**产品第一次在事情发生之前就替用户想到了**。

**为什么需要 AI**：

- **理解**："家里纸巾没了"→ 自动入清单并预估上次购买到现在的消耗
- **编排**：菜谱缺食材 + 耗材预警 → 合并成一张周末采购清单（跨模块联动，L4 雏形）
- **学习惯**：买同样的东西总是同一个超市/同一档金额 → 下次给候选

**与现有资产的联动（这是选它的决定性理由）**：

```
记账（已有）──→ 记"买纸巾 ¥45" → 自动归"日用"并刷新耗材余量估算
用餐（已有）──→ 菜谱缺食材 ──→ 进清单（C8 最小表）
日程（C13）──→ 周末采购提醒 ─→ 清单作为提醒的附件
通知（C5）───→ 阈值预警 ────→ "纸巾预计本周用完，加入清单？"
```

**V1 范围（最小可用，不做过重）**：一张**家庭共享清单**（增删勾选，幂等可撤销）+ **耗材余量记录**（一句话/扫码记"又用完一卷"）+ **阈值提醒**进通知中心。**不做**：比价、代下单、店铺分区、库存级管理（阶段 D）。

> 与 `product-inspiration-01.md` §5.3 / 研究报告附录 A 的 C8 关系：C8 原登记为"购物清单 V1 最小表 + 耗材完整版阶段 D"。**本文的建议是把 C8 的耗材最小形态从阶段 D 提到 V1 阶段 B**（只做"记录 + 预警"，不做完整囤货管理）。⚠️ 需在 §10/§8 落位后实施。

### 4.2 家庭档案 · 建议 V2（信任建立之后）

**用户问题**："保单在哪""发票找不着""家电保修期是不是过了"——低频，但**出事时极其重要**，且当前完全靠人脑和抽屉。

**为什么留 V2**：档案是**敏感数据**（证件、病历、保单）。家人把这类东西交给产品的前提，是产品已经通过记账/家务/报饭建立了"可核对、可撤销、不丢失"的信任。**在 L3 深耕未稳前碰它，是用信任换功能**——不值得。

**如果做，长什么样**：拍照/上传 → 提取关键字段与**到期日** → 到期前进通知中心（与账单到期同一出口）。核心价值不是"存"，是**"到点提醒你该续了"**。

**V1 可做的非敏感子集**：家电保修期、会员/订阅到期日（纯日期，不涉及证件）——可作为 C16 周期账单的延伸，先验证"到期提醒"这条链路。

### 4.3 用药与健康关怀 · 建议 V2/V3

**用户问题**：老人慢性病用药、孩子疫苗时间表、年度体检——**家人最焦虑但最没有承载体**的一类事。当前靠群里喊和备忘录。

**为什么是最高价值但最晚做**：

- 价值最高：它直接命中"老人与小孩"——产品价值网络中最脆弱、也最决定周活跃的两个人群
- 门槛最高：用药提醒**错了代价极大**（`AI-PRD §6.2` 的安全否决项思维：涉及健康的功能必须人工确认 + 不可静默吞错）
- 因此：V1 **不做用药提醒**；V2 可以先做**记录与查看**（用药清单、体检记录、疫苗时间表——纯信息，不涉及提醒与推断）；V3 在 C4 打扰预算与审计成熟后再做**主动提醒**

**明确不做**：任何健康建议、任何症状推断、任何与医疗系统的对接（`AI-PRD §7` 的确定性边界）。

## 5. AI 的差异化坐标

**判据不变（沿用研究报告 §10）**：**AI 的价值以"减少了用户的一次操作"计价**。

| AI 能力        | 场景                                          | 当前实现度        | 属于哪条主脉 | 依赖                |
| -------------- | --------------------------------------------- | ----------------- | ------------ | ------------------- |
| **理解**       | "纸巾没了"→ 清单 + 预估消耗                   | 部分              | 输入         | —                   |
| **主动盯**     | 到点提醒、耗材预警、异常检测、长期未打卡      | **0**             | 跑腿         | **C4/C5（阶段 A）** |
| **跨模块编排** | "按这周菜单买菜"→ 菜谱→缺食材→清单→记账整条链 | **0**             | 跑腿/智能    | C8 + C16            |
| **学家庭习惯** | 报饭规律、分类记忆、金额候选、"变了才报"      | 0（分类记忆未做） | 输入/智能    | 历史数据            |
| **推荐下一步** | "还有 2 个任务没打卡""今晚 3 人吃饭做 4 人份" | 0                 | 跑腿         | 各模块缺口字段      |

**核心论点**：理解（STT/NLP）与执行（工具调用）**规则系统也能做**。真正非 AI 不可的是**主动盯 + 编排 + 学习**这三件——它们分别对应"省记忆成本""省判断成本""省操作成本"。

**这也是为什么第五模块（采购囤货）值得进 V1**：它是**唯一一个在"主动盯"和"编排"两件事上都有自然落点的模块**（阈值预警 + 菜谱联动），能成为 L4 跨模块联动的第一个真实场景。

## 6. 取舍：明确不做的清单

| 不做的事                    | 为什么                                                                             |
| --------------------------- | ---------------------------------------------------------------------------------- |
| **社交/动态广场/好友圈**    | `AI-PRD §7` 禁项；家庭产品不靠连接陌生人获客，且公开化会摧毁"温和提示"的设计（P6） |
| **电商代购/比价/代下单**    | 交易把产品拽向"导购平台"，且售后/合规/资金安全完全超出家庭事务范畴；清单止于"清单" |
| **金融：理财/借贷/AA 结算** | `AI-PRD §7` 禁项；记账止于"记录与预算"，不碰资金流转                               |
| **位置共享**                | 隐私（`product-inspiration-01.md` §3.4 已判定不做）                                |
| **通用闲聊/情感陪伴**       | `AI-PRD §7` 禁项；信任来自"把事办到位"，不是"会聊天"                               |
| **健康管理/症状推断**       | 确定性边界（§4.3）；AI 不做任何健康判断                                            |
| **企业级项目管理**          | 子任务/甘特图/复杂审批流——家庭的弱协作属性不需要（§1.1）                           |

**新增模块的筛选线（再强调一次）**：**它是否替收口者省了一次脑子？** 走不通这条线的模块，做得再炫也不要。

| **V1-B** | 四模块深耕到 ≥ L3（FR-CHORE/MEAL/BILL/CAL）                                                  | `AI-PRD §10`          |

| **V1-C** | 智能默认（分类记忆、报饭规律）、异常检测、周报——**让"学家庭习惯"第一次成立**                 | 研究报告 §15 阶段 C   |
| **V2**   | ★家庭档案（非敏感子集可提前：保修期/订阅到期）· ★健康记录（只记录不提醒）                    | 本文 §4.2 / §4.3      |
| **V3**   | ★用药提醒（需 C4 打扰预算 + 人工确认成熟）· ★家庭投票 · ★外部通知聚合 · 家政信息（不做交易） | 本文 §4.3 / §6        |

**落位原则**：每个新模块 = **权限矩阵加一列 + 工具注册 + Today 加一屏**（`tool-perms-config.md` 已设计的扩展模式）。新模块**必须**同时有：写操作可撤销（ADR-004）、权限双保险（ADR-005）、审计留痕——否则不立项。

## 9. 与既有研究的一致性检查

| 检查项              | 结果                                                                                                                    |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| 定位                | 与研究报告 §1.4 / 灵感 §1 的"家庭事务中枢，非记账应用"一致；第五模块是**中枢的供给层补全**，不是定位漂移                |
| 三条主脉归属        | 采购囤货 = 跑腿（预警）+ 输入（一句话记消耗）；档案 = 可见（凭证）+ 跑腿（到期提醒）；健康 = 跑腿（未来）+ 信任         |
| 设计原则            | C17 命中 P6（缺口显式：清单缺什么）、P1（一句话记消耗）、P4（默认值）；C19/C20 命中 P5（先确认后执行）与 P7（打扰预算） |
| 深度分级            | C17 在 V1 达到 L1–L2（可用+完整）即可，**不要求 L3**——第五模块的 L3 不是 V1 出口判定项（避免扩大出口范围）              |
| §7 禁项             | 无新增禁项触碰；投票/外部通知/家政三项均落在 V3 且不做交易                                                              |
| 与 `ux-exploration` | 走查的 5 个机会不受影响；耗材预警是走查未覆盖的新增价值（走查样本里没有耗材场景，属增量发现）                           |
