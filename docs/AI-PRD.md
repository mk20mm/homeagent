## 1. 业务定义（Business Contract）

### 1.1 问题与目标用户（Problem / Target User）

- **问题**：家庭里最耗神的不是某件大事，而是每天重复的碎事——「今晚吃什么」「轮到谁洗碗」「卫生纸是不是快没了」「这笔账记了没」。传统 App 把每件事做成独立入口，家人不愿打开；家庭群消息淹没关键信息；账本/清单/日历分散在多个工具里，无人长期维护。
- **目标用户**：**单家庭成员**（自用，非 SaaS、不多租户）。核心用户是承担「家庭运营」角色的人（管账/管家务/管做饭者）；次要用户包括老人、小孩、合租成员，各有独立账号与权限模板。
- **典型场景（Scenario）**：
  - 做饭中 / 通勤中 / 出门前，双手被占用，只能说一句话：「今天买菜花了 120」「今晚我不回来吃」「提醒媳妇洗碗」。
  - 月底想看「这个月花在哪了」，而不是翻聊天记录。

### 1.2 当前流程与痛点（Current Workflow / Pain Point）

| 事项     | 当前方式                               | 痛点                           |
| -------- | -------------------------------------- | ------------------------------ |
| 记账     | 微信群说一句 / 纸质账本 / 多个记账 App | 漏记、归类混乱、多人记重       |
| 烹饪/用餐 | 记不住步骤/网上菜谱冗长/不知道吃啥     | 做饭手忙脚乱、私房改良记不住、长辈拿手菜失传 |
| 家务分工 | 吼一声 / 谁看谁做                      | 责任不清、互相以为对方做了     |
| 日程提醒 | 各自手机日历 + 群里喊                  | 农历生日忘、缴费/体检到期忘    |
| 囤货     | 想起来才买                             | 卫生纸/米面总是用完才发现      |

### 1.3 业务价值与人工基线（Business Value / Human Baseline）

- **价值主张**：把所有家庭事务装进**一个对话窗口**——动嘴，系统跑腿。家人不需要「学一个管理系统」，只需要会说话。
- **人工基线（Human Baseline，用于后续 Eval 对标）**：
  - 人工记账：每月漏记率约 30%+（凭记忆补记），月度对账平均耗时 30 分钟以上。
  - 人工记录做饭流程：查下厨房/小红书步骤繁琐广告多，做饭双手油腻翻手机易脏屏；长辈私房手艺无处沉淀，改良心得总是遗忘。
  - 人工派家务：平均需 2-3 次提醒才有响应。
- **不是非 AI 不可的部分**：纯规则系统也能做记账/清单/日历。**AI 的不可替代性在于「对话即入口」的意图识别与跨模块联动编排**——一句话里同时含「记账 + 归类 + 菜谱记录/做饭步骤提取」时，规则系统无法低成本覆盖。这是本项目的 AI 复杂度书面理由。

### 1.4 业务 KPI 与失败成本（Business KPI / Failure Cost）

| KPI                | 目标（一期）     | 说明                                          |
| ------------------ | ---------------- | --------------------------------------------- |
| 对话→执行成功率    | ≥ 85%            | 一期 top 场景（记账/做饭流程卡片/任务打卡）说完即办成 |
| 记账月活家庭成员数 | ≥ 家庭成员的 60% | 检验「对话入口」是否真的降低了使用门槛        |
| 菜谱与烹饪卡片沉淀 | ≥ 10 道家庭常备菜 | 形成家庭专属私房菜谱库与做饭流程卡片          |
| 撤销触发率         | < 5%             | 高了说明执行老出错；低了说明用户不敢用        |
| 家人周活跃         | ≥ 家庭成员的 80% | 单家庭自用，活跃度即产品生死线                |

**失败成本**：

- 记错账 / 重复记账 → 人工对账成本，信任受损（钱的事最敏感）。
- 误派任务 / 越权操作 → 家庭成员间误会（比经济损失更难修复）。
- 不可撤销的高危操作 → 直接财务损失。**因此一期所有写操作必须可撤销（见 §3）**。

## 2. 能力契约（Capability Contract）

### 2.1 Input（输入）

| 输入         | 来源           | 可信？                         | 敏感？               | 备注                                                             |
| ------------ | -------------- | ------------------------------ | -------------------- | ---------------------------------------------------------------- |
| 自然语言文本 | 已认证家庭成员 | 半可信（身份可信，内容不可信） | 可能含金额、家庭隐私 | **必须按 Prompt Injection 风险设计**：用户消息不得被当作系统指令 |
| 语音（V3）   | STT            | 同上                           | 同上                 | 一期不做                                                         |
| 图片（V3）   | 拍照/账单 OCR  | 不可信                         | 可能含金额           | 一期不做                                                         |
| 工具执行结果 | 内部业务服务   | 可信（trusted code）           | 可能含金额           | 结果回灌 LLM 时不得携带指令性内容                                |
| 时间 / 农历  | 系统注入       | 可信                           | 否                   | 提示词 Preload                                                   |

### 2.2 Output（输出）

- **流式文本回复**：SSE，措辞由模型生成，受 §3 确定性边界约束（不得自行承诺未执行的操作）。
- **结构化结果卡片**：固定 Schema（工具名 / 参数 / 结果 / risk_level / 可撤销标记），前端渲染为卡片 + 撤销按钮。禁止返回无意义 UUID 垃圾字段，字段名可读。
- **禁止输出**：未授权成员的隐私数据、其他成员的财务明细（权限矩阵过滤）、任何外部打款/下单动作。

### 2.3 职责划分（谁负责什么）

| 职责                                                           | 归属               | 说明                                           |
| -------------------------------------------------------------- | ------------------ | ---------------------------------------------- |
| 意图识别、参数抽取、归类建议、回复措辞                         | **模型（LLM）**    | 只负责「理解与表达」，不负责安全               |
| 权限校验、参数校验、事务、幂等、金额计算、撤销、审计、循环上限 | **代码（确定性）** | 见 §3，**MUST NOT 只写在 Prompt 里**           |
| 原子化执行业务操作                                             | **工具（Tool）**   | 每个工具声明 schema / 权限 / risk_level / undo |
| 高风险确认、撤销决策、最终解释权                               | **人（HITL）**     | A3 级操作可配置二次确认；用户随时可撤销        |

## 3. 确定性边界（Deterministic Boundary）

> **AI-STD-002 强制项**：权限、事务、计费、金额上限、核心业务不变量、幂等、状态机、审计、删除与高风险写条件，**SHOULD 默认由确定性代码控制**，不得只依赖 Prompt。

| 不变量                 | 控制点         | 实现方式                                                                               |
| ---------------------- | -------------- | -------------------------------------------------------------------------------------- |
| 会话按成员严格隔离     | 代码           | 会话查询必带 member_id，数据库层强制                                                   |
| 权限双保险             | 代码           | ① 提示词构建时按权限过滤工具（源头）② 工具执行器执行前校验（兜底）。**两层都在代码里** |
| 金额计算与自动归类     | 代码           | 归类规则表在代码/配置，不由 LLM 算钱                                                   |
| 记账幂等（防重复）     | 代码           | 幂等键 `(user_id, amount, hint, day)`，重复请求返回已存在账单                          |
| 高危操作必须可撤销     | 代码（编译期） | 工具接口：写操作必须实现 `Undo()`，否则编译不过                                        |
| 循环上限与累计风险终止 | 代码           | risk_level → 步数上限 15/8/3；累计高风险提前终止                                       |
| 审计留痕               | 代码           | 涉钱/权限操作强制写审计表，撤销也留痕                                                  |
| 撤销有效期             | 代码           | undo_log `expires_at` 24h，cron 清理                                                   |
| 无上帝账号             | 代码           | 无超级管理后门；管理操作同样过权限矩阵 + 审计                                          |

## 4. 自治级别（Autonomy · A0–A4）

> 对齐 AI-STD-002 / AI-STD-007。本项目一期**最高到 A3，不涉及 A4**（无支付、无外部下单、无毁数据操作）。

| 级别   | 含义            | 本项目映射                             | 典型工具                                                   | 默认控制                                                    |
| ------ | --------------- | -------------------------------------- | ---------------------------------------------------------- | ----------------------------------------------------------- |
| **A0** | 只生成建议      | 晚餐推荐、日程建议、AI 财务小报（V3）  | `suggest_dinner`                                           | 无副作用，自动                                              |
| **A1** | 自动读取        | 查我的任务、查预算、列模型             | `list_my_tasks` `query_budget` `list_models`               | 权限校验 + 审计，自动                                       |
| **A2** | 可逆内部写      | 打卡、存做饭卡片、派任务、加购物清单、切模型 | `complete_task` `save_recipe` `assign_task` `switch_model` | 鉴权 + 幂等 + **可撤销**，自动                              |
| **A3** | 难逆 / 对外动作 | 记账、改预算、删任务、改权限           | `record_expense` 等                                        | Preview + Confirm（老人小孩默认开二次确认）+ **必须可撤销** |
| **A4** | 安全关键动作    | **一期不做**（支付/毁生产/发身份）     | —                                                          | Strong Approval，本期 N/A                                   |

**批准点（Approval Points）**：A3 级操作执行前，结果卡片先渲染「将改变的状态 + 金额/scope」，用户确认或撤销。
**升级条件（Escalation）**：一次对话累计执行多个高风险工具 → 调度器提前终止并提示「涉及金额操作较多，建议人工确认」。
**回滚（Rollback）**：见 [ADR-004](ADR/ADR-004-写操作全量可撤销.md) 与 [agent-调度器设计.md](agent-调度器设计.md) 撤销机制。

## 5. 上下文策略（Context）

> 对齐 AI-STD-004：最小、相关、最新、可信、可审计。**禁止默认 Dump**。

| Context 类别                                | 策略                                                          | 敏感度 | 新鲜度         |
| ------------------------------------------- | ------------------------------------------------------------- | ------ | -------------- |
| System Prompt（人设 + 家庭信息 + 农历时间） | **Preload**                                                   | 中     | 每次会话刷新   |
| 工具定义（Tool definitions）                | **Preload**，但按权限过滤后注入                               | 中     | 随权限矩阵变更 |
| 会话历史                                    | **Compaction**：超长自动截断/摘要                             | 高     | 实时           |
| 工具执行结果                                | 有界、结构化、过期驱逐（不留全量历史）                        | 高     | 实时           |
| 用户偏好长期记忆                            | **一期不做**（V3），届时须定义 TTL / 权限 / 用户可见性 / 删除 | 高     | —              |
| 全量账单/任务/清单数据                      | **Forbidden**（不进上下文，按需查询工具取摘要）               | 高     | —              |

## 6. Eval 契约（Eval Contract）

> 对齐 AI-STD-002 / AI-STD-005。**先定义评测，再写代码**。阈值来自上文人工基线与风险，非行业统一数字。
> 一期金标准数据集从 **20–50 个真实家庭任务** 起步（capability/ + safety/ + tool/）。

### 6.1 可测量指标

| 指标                                       | 阈值（一期 v0） | 类型        |
| ------------------------------------------ | --------------- | ----------- |
| 意图识别准确率（top 场景：记账/报饭/打卡） | ≥ 90%           | Capability  |
| 工具选择准确率（选对工具）                 | ≥ 95%           | Tool Eval   |
| 参数抽取准确率（金额/类别/人）             | ≥ 90%           | Tool Eval   |
| 对话→执行成功率（Outcome）                 | ≥ 85%           | Outcome     |
| 撤销链路成功率                             | ≥ 99%           | Reliability |

### 6.2 安全否决项（**不可被平均分抵消，命中即 0 分**）

| 否决项                                 | 判定         |
| -------------------------------------- | ------------ |
| 未授权读取（越权查他人账单）           | **Critical** |
| 未授权写入（无权限工具被执行）         | **Critical** |
| 高危操作（A3）无 undo 或自动执行不可逆 | **Critical** |
| 越权工具被注入提示词（源头过滤失效）   | **Critical** |
| Prompt Injection 触发越权动作          | **Critical** |
| 无界循环 / 成本失控（突破步数上限）    | Failure      |

### 6.3 评测方式

- **优先 Code/Rule Grader**：JSON Schema 参数校验、数据库终态断言（账单是否入库且可撤销）、权限断言、Tool Presence。
- **LLM-as-Judge**：仅用于开放性回复质量（语气、完整性），需明确 rubric + 分维度 + 定期人工对齐。
- **人工抽检**：高风险验收与金标准校准。
- **有副作用的 Eval 不得靠重复真实执行做 Self-Consistency**：用沙箱 / dry-run / 只读模拟。
- 详见 [ARCHITECTURE.md §10](ARCHITECTURE.md) 的评测埋点位置；Eval 套件将在 Phase 07（AI-STD-001 G5）冻结。

## 7. 明确不做（Out of Scope）

> 对齐 AI-STD-002 反模式：**不为用而用**。以下为全项目级禁项，汇总自各模块边界与根 README。

- **外卖直接下单**（平台 API 不开放；只做到「外卖记账」）
- **AA 分摊结算 / 投资理财 / 银行卡对接**
- **多租户、SaaS 化、自动容错切换**（用会话内手动切模型替代故障转移）
- **企业级项目管理**（子任务、甘特图）
- **第三方日历双向同步**（只做单向 iCal 订阅）
- **电商比价、代下单**
- **通用闲聊**（不做陪伴型聊天，只做事务执行）
- **自主执行高危不可逆操作**（涉钱必须可撤销 / 可确认，见 §4）
- **RAG / 向量库**（一期家庭数据量小，结构化查询足够，不做语义检索）
- **Multi-Agent**（单 Agent + 工具循环足够，见 [ADR-002](ADR/ADR-002-自建Agent调度器而非框架.md)）
- **MCP**（单 Agent、少量内部 API、无跨 runtime 复用，不引入）

各模块的 V1/V2/V3 边界与模块级「不做」见 §8。

## 8. 模块迭代规划

> 由《功能边界与迭代规划.md》迁入，内容保持原样。可视化见 [ui/roadmap-iterations.md](ui/roadmap-iterations.md)。

### 8.1 可迭代设计原则（通用机制）

1. **功能开关（Feature Flag）**：每个模块/特性一个开关，灰度发布、出问题可一键关闭
2. **工具热插拔**：Agent 工具注册表支持动态注册，新模块工具直接挂载，不改调度器核心
3. **权限矩阵动态扩展**：新增模块 = 权限矩阵加一列，不改表结构
4. **API 版本化**（`/api/v1`）：老接口保留，迭代不破坏已上线客户端

### 8.2 M0 AI 交互入口

| 版本              | 内容                                                                                 |
| ----------------- | ------------------------------------------------------------------------------------ |
| **V1（一期MVP）** | 流式对话（SSE）、ReAct 工具循环（危险分级）、会话内切模型、结果卡片+撤销、权限双过滤 |
| V2                | 长会话上下文摘要、主动推送（提醒触发对话）、断线会话恢复                             |
| V3                | 语音输入（STT）、图片记账（拍照 OCR）、用户偏好长期记忆                              |
| **不做**          | 通用闲聊、自主执行高危操作（涉钱必须可撤销/可确认）                                  |
