# ADR-006：以家庭任务执行协议强化单 Agent 调度

- 状态：提议（设计完成，待实施验证）
- 日期：2026-10-01
- 关联标准：AI-STD-002/003/004/005/006

## 背景

现有 ReAct 工具循环已能调用财务、家务、报饭和出行工具，但存在执行后风险计数、撤销持久化与业务写入分离、整轮末尾保存历史等缺口。用户明确将 AI 调度入口的驾驭工程作为第一优先级，再扩展吃、事、钱、出行、健康和学业能力。

## 决策

保留自建单 Agent，通过 AgentRun/RunStep/RunEvent 管理家庭事务；必要确认绑定步骤、参数版本和有效期，不独立建设通用审批平台。模型提出目标与步骤，代码在执行前控制权限、参数、风险、预算和确认。本地写入用显式事务 Provider 原子提交业务数据、撤销、必要审计与步骤成果；设备命令单独持久化、派发与观察。领域模块通过统一工具协议接入，页面与对话共享领域数据。

2026-10-01 用户修订：第一步只交付设计，实施给 Gemini；聚焦财务、家务、厨房。家务包含个人 HA 和扫地机真实执行，厨房包含家庭菜谱与多菜协同；报饭不作为核心。任务协议简化为 Run/Step/Event，按需确认不独立建通用审批平台。权威设计见 [第一步架构](../homeagent-v1-architecture.md)；外部设备副作用边界见 [ADR-007](ADR-007-本地撤销与设备补偿.md)。本 ADR 不表示 API 或存储模型已改动。

## 后果

获得可恢复、可核对和可评测的执行轨迹；新工具不需复制一套执行护栏。代价是新增运行状态与事务接口、旧 SSE 的兼容迁移，以及批准/部分完成的交互。通过分阶段契约生成、故障注入测试与保留简单请求路径控制成本。

## 备选方案

- 只改提示词：无法保证撤销原子性、恢复、幂等和执行前限制。
- 立即按六域拆多个 Agent：当前没有独立并行净收益证据，会增加协调和权限传播成本。
- 全部写成固定流程：适用于周期提醒，但不覆盖开放的跨域家庭请求。
- 一次性上齐六域：新工具会放大底座缺口，先用晚餐场景验证公共协议。
