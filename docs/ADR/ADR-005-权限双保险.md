# ADR-005：权限双保险——提示词层过滤 + 执行层校验

- **状态**：接受（设计阶段，Phase 03）
- **日期**：2026-09-15
- **决策者**：项目维护者
- **关联标准**：AI-STD-002（确定性边界 MUST NOT 只写在 Prompt 里）、AI-STD-007（R1+ 身份/最小权限/审计、Prompt Injection 攻击面）

## 背景

家事 Agent 服务单家庭多角色：大人、老人、小孩、合租成员各有不同权限。例如：

- 小孩不应能改预算、不应能看家庭全部账单明细
- 老人只用到记账和报饭，工具多了反而困惑
- 只有家长能改权限矩阵

LLM 的工具选择基于提示词里的工具清单。**如果权限只靠提示词控制**，一次提示词构建错误、一次注入、一次模型抽风，越权就发生了；**如果只在执行时校验**，模型会反复尝试无权工具，浪费 token 且体验差（模型不停说「我来试试」然后失败）。

## 决策

**权限双保险，两层都在确定性代码里**：

1. **提示词层过滤（源头）**：系统提示词构建器只把**该用户权限内的工具**注入清单。模型从根上看不到无权工具，降低误调用概率，同时按角色精简工具集（老人简洁、小孩活泼）。
2. **执行层校验（兜底）**：工具执行器执行前**强制**做权限校验 + 参数校验（JSON Schema），与提示词层完全独立。

补充约束：

- 会话按成员严格隔离（member_id 贯穿会话查询与数据访问）
- 无上帝账号：管理操作同样过权限矩阵 + 审计
- 越权尝试写审计日志，供安全 Eval 检测

## 后果

### 正面后果

- **纵深防御**：任何单层失效（提示词注入、模型越界、缓存错误）都不构成越权
- **体验与成本兼得**：源头过滤让模型不浪费 turn 在无权工具上；兜底校验保住安全下限
- **对齐 AI-STD-002 强制项**：权限这类核心不变量在代码里，不只存在于 Prompt——满足「Deterministic Boundary MUST NOT 只写在 Prompt 里」

### 负面后果 / 风险

- **两套权限逻辑需保持一致**：提示词过滤清单与执行校验规则如果不同步，会出现「看得见调不了」或「看不见却能调」的错配
- **角色模板维护成本**：老人/小孩/合租的预设权限需随模块扩展持续更新

### 缓解措施

- **单一数据源**：权限矩阵是唯一事实源，提示词过滤与执行校验**都从同一份矩阵读取**，不存在两份配置
- **权限矩阵动态扩展**：新增模块 = 矩阵加一列，不改表结构（见 [AI-PRD.md §8.1](../AI-PRD.md)）
- **安全 Eval 覆盖**：越权读取/写入 = Critical 否决项；越权工具出现在提示词 = Critical（[AI-PRD.md §6.2](../AI-PRD.md)）
- 审计日志记录所有权限事件，异常尝试可告警

## 备选方案

| 方案                         | 为什么不选                                                                                                           |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| **只在提示词里声明权限规则** | 违反 AI-STD-002/007：Prompt 可被注入、可被模型忽略，且无法审计执行路径                                               |
| **只在执行层校验**           | 安全达标但体验差、成本高：模型看得见无权工具会反复尝试，浪费 turn 与 token，且回复可能声称已执行（实际被拒）造成误导 |
| **再加一个 LLM 做安全判别**  | 违反 AI-STD-007「禁止把第二个 LLM 当唯一安全闸门」；确定性权限用代码判更准更省                                       |
