# ADR — 架构决策记录（Architecture Decision Records）

> 对齐 **AI-STD-003 / AI-STD-006**。ADR 记录「为什么这么选」，代码只记录「选了什么」。
> 偏离 AI-STD 中 MUST 级条款时，必须以 ADR / Waiver 说明理由（Reason / Risk / Compensating Control / Owner / Expiry / Review）。

## 格式约定

每条 ADR 固定结构：

- **标题**：`ADR-XXX-简短决策名`
- **状态**：提议 / 接受 / 已落地 / 已废弃
- **日期** / **关联标准**
- **背景（Context）**：问题、约束、备选
- **决策（Decision）**
- **后果（Consequences）**：正面 / 负面与风险 / 缓解
- **备选方案（Alternatives）**：为什么不选

## 编写规则

1. 一条决策一篇，标题即结论
2. 写「不选什么」和「代价是什么」，不只写优点
3. 状态变更（如废弃）保留原文，追加变更记录，不改写历史
4. 数量从简：不为凑数造 ADR，也不让关键选型只活在聊天记录里
