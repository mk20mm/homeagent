# ADR-002：自建轻量 Agent 调度器，不引入重型 Agent 框架

- **状态**：接受（设计阶段，Phase 03）
- **日期**：2026-09-15
- **决策者**：项目维护者
- **关联标准**：AI-STD-003（架构：组件必须为解决具体工程问题存在）、AI-STD-004（工具工程）

## 背景

项目核心是「对话→工具执行→撤销」闭环。调度器要做的只有四件事：

1. 维护会话与历史
2. 构建提示词（含权限内工具清单）
3. 跑 ReAct 循环（LLM 输出含 tool_call 就执行并回传，直到无调用）
4. 执行工具时做权限校验、参数校验、写 undo_log、写审计

工具数量少（一期约 10 个），全部是内部业务 API，**没有跨 runtime 复用、没有多团队共用、没有多 Agent 编排需求**。

## 决策

**自建轻量工具调度器**（工具注册表 + Function Calling 执行循环 + 结果回流），核心模式采用行业标准 **ReAct loop**（与 OpenAI Function Calling / Vercel AI SDK multi-step 同一模式）。

不引入 LangChain / LangGraph / AutoGen 等重型框架，不引入 MCP，不引入 Multi-Agent。

## 后果

### 正面后果

- **完全可控**：危险分级（15/8/3 步上限）、累计风险终止、权限双保险、撤销联动等安全核心逻辑全在自家代码里，不被框架黑盒吞掉
- **零依赖漂移**：框架版本升级带来的行为漂移（AI-STD-010 关注点）由自己掌握
- **实现量小**：核心就是一个循环 + 一个注册表，`go-openai` 处理 OpenAI 兼容供应商的流式与工具调用，Anthropic/Ollama 单独适配
- **符合最小必要原则**：AI-STD-003 明确「禁止为画完整架构图引入 Planner / Memory / Multi-Agent」，本项目不需要这些

### 负面后果 / 风险

- **轮子成本**：流式 SSE、工具循环、断线重连、用量埋点都得自己写与自己测
- **缺少框架自带设施**：如现成的 trace / checkpoint / retry 中间件

### 缓解措施

- 复用成熟库降成本：`go-openai`（OpenAI 兼容流式+工具调用）、Gin 中间件（认证/权限）、robfig/cron（定时任务）
- 运行时约束按 AI-STD-003 补齐：max turns / 超时 / 取消 / 成本上限 / checkpoint / 重试 / 并发 / trace（详见 [ARCHITECTURE.md §2.2](../ARCHITECTURE.md)）
- 工具接口内建安全约束：写操作必须实现 `Undo()`（见 [ADR-004](ADR-004-写操作全量可撤销.md)）

## 备选方案

| 方案                      | 为什么不选                                                                                                                    |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| **LangChain（Python）**   | 需换语言（与 [ADR-001](ADR-001-技术栈选型Go.md) 冲突）；抽象层重，大量用不上的链；行为黑盒，安全核心逻辑反而难控              |
| **LangGraph**             | 状态机编排强，但本项目是**开放多步**而非可预写路径，用不上图编排；且仍是 Python 生态                                          |
| **Vercel AI SDK（Node）** | multi-step 工具循环确实是同款模式，但会绑死 Node 全栈，且危险分级/撤销/审计等领域逻辑还是要自己写                             |
| **MCP 工具协议**          | AI-STD-004 明确：单 Agent、少量内部 API、无跨 runtime 复用时**通常不必用**。MCP 也不替代 IAM / 事务 / Eval / 审计，只增复杂度 |
| **Multi-Agent**           | 无 Eval 证据支持必要（工具少、无上下文隔离需求、无并行净收益），AI-STD-003/001 要求 Multi-Agent MUST 由 Eval 证明             |
