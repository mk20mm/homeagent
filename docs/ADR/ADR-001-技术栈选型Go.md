# ADR-001：后端技术栈选 Go

- **状态**：接受（设计阶段，Phase 03）
- **日期**：2026-09-15
- **决策者**：项目维护者
- **关联标准**：AI-STD-003（架构）、AI-STD-008（生产与可观测）

## 背景

家事 Agent 是单家庭自用、部署在单台 VPS 上的应用。后端需要同时处理三类刚需：

1. **流式输出**：SSE 长连接把 LLM 生成逐字推给前端
2. **长连接 / 并发**：多家庭成员同时对话、工具并发执行
3. **定时任务**：提醒、账单到期、周报、undo_log 清理

同时项目对长期可维护性要求高（个人长期项目，不想频繁重写），对供应链安全敏感（家庭财务数据）。

备选语言：Node/TypeScript、Python、Rust、Java/Kotlin。

## 决策

后端主语言采用 **Go**，Web 框架用 **Gin**。

## 后果

### 正面后果

- **性能/并发**：goroutine 天然适合流式输出、长连接、定时任务，三者在本项目都是刚需
- **长期安全/扩展**：静态类型 + 内存安全 + 少依赖，供应链风险低，上限最高
- **部署省心**：单二进制 + Docker，适合自用单 VPS，无运行时环境依赖

### 负面后果 / 风险

- **AI 生态弱**：Go 的 LLM / Agent 生态不如 Python（LangChain、LlamaIndex 等）成熟，Agent 调度框架需自建
- **与前端语言不通**：后端 Go、前端 TS，类型不共享

### 缓解措施

- AI 生态弱 → 自建轻量调度器（见 [ADR-002](ADR-002-自建Agent调度器而非框架.md)），反而获得更高可控性
- 前后端类型不通 → 用 **OpenAPI 3.0 契约 + oapi-codegen** 生成 Go server 桩与 TS client，契约即代码，桥接类型

## 备选方案

| 方案            | 为什么不选                                                                                                           |
| --------------- | -------------------------------------------------------------------------------------------------------------------- |
| **Node/TS**     | 前后端同语言最省心，但长连接 + 定时任务 + CPU 密集的并发模型不如 goroutine；单进程事件循环在工具并发执行上需额外编排 |
| **Python**      | AI 生态最强，但部署体验差（虚拟环境/依赖漂移）、动态类型对长期维护与供应链管控不利、并发模型弱                       |
| **Rust**        | 性能与安全上限最高，但开发速度慢、生态偏系统编程，对一个家庭应用过重                                                 |
| **Java/Kotlin** | 生态成熟，但 JVM 启动慢、内存占用高，单 VPS 自用不划算                                                               |
